The reframe: you never need to re-run the CORDIS pipeline

The slow tag-calls step only has to run once, anywhere. After that, snapshot the database to a file and just load the file into whatever production DB you want. Neo4j has first-class offline
backup/restore for exactly this:

# 1. Run the slow CORDIS pipeline once (local), then stop Neo4j and dump it:
bin/neo4j-admin database dump neo4j --to-path=/path/to/dumps/

# 2a. Load that dump into ANY Neo4j (Railway container, local, etc.):
neo4j-admin database load neo4j --from-path=/path/to/dumps --overwrite-destination=true

# 2b. Or push the SAME dump straight into Aura — no re-population:
bin/neo4j-admin database upload neo4j \
  --from-path=/path/to/dumps \
  --to-uri=neo4j+s://<your-aura-id>.databases.neo4j.io \
  --overwrite-destination=true

That database upload command means even staying on Aura, you don't have to repopulate — you run the pipeline once locally, dump, and upload the dump. Days of API calls → one ~minute upload. So

If you still want Railway (cost / single platform)

It's straightforward — same pattern as deploying any Docker DB there:

1. New service from the neo4j Docker image (e.g. neo4j:5-community).
2. Attach a persistent volume mounted at /data — this is the critical part. Without it, data is wiped on every redeploy. Railway volumes survive restarts/deploys.
3. Env vars: NEO4J_AUTH=neo4j/<password>, plus any memory tuning (NEO4J_server_memory_heap_max__size, etc.).
4. Expose the Bolt port 7687 (and 7474 for Browser if you want it). Point your bathe Railway internal/private URL.
5. Seed it by loading your dump (option 2a above) into the volume.

The honest catch: moving to Railway trades a recurring-cost saving for operational responsibility (backups, upgrades, memory tuning, securing Bolt). Since your data is derived/reproducible from CORDIS + a dump file, that risk is low for you — losing the volume just means re-loading the dump, not re-running the pipeline.

My recommendation

1. Regardless of host: fix the repopulation pain now by dumping your populated DB to a .dump file and version it (or stash it in object storage). That single artifact is your "days of work, frozen."
2. Then decide hosting on cost/ops appetite alone — Aura if you want zero-mainten Railway if you'd rather save money and own backups. Either way you seed from thesame dump, so the migration is reversible and cheap.
